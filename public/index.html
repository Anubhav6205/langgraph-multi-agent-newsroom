Multi-Agent Newsroom (LangGraph)

A research-and-writing assistant with a supervisor, a corrective RAG researcher, a guardrail and a human review step. Python, LangGraph, LangChain, FastAPI.

Source on GitHub LinkedIn

This is a project showcase, not the live app. The real system calls OpenAI (gpt-5-mini), Tavily and a local Chroma vector store, so it needs API keys and a running server. Those do not fit a free static deployment. This page shows the architecture and lets you step through the graph's control flow. The steps are illustrative and follow the routing rules in the code. No model is called and no generated text is shown.

Graph

The outer graph is defined in graph.py. Pick a scenario below to see which node runs at each step.

The supervisor picks the next node with a structured output, and an InMemorySaver checkpointer holds state per thread. The human step can also send the draft back to the writer (see the "Human declines" scenario).

Step through a run

    Corrective RAG researcher

    The researcher is its own compiled graph (agents/researcher.py). It retrieves, grades what came back, and rewrites the query if the results are not relevant. Choose the "Researcher: corrective RAG loop" scenario above to step through it.

    When the agent answers without a tool call, tools_condition routes to END and the outer wrapper returns the last message to the supervisor.

    What each part does

    Guardrail

    Screens the request before any other agent runs. Blocks prompt-extraction attempts, personal-data requests, off-topic input and obvious jailbreak patterns. A blocked request ends the run with an error reason.

    Supervisor

    Routes one step at a time with a strict sequence: researcher, then writer, then editor, then back to the writer if the editor left a critique, otherwise FINISH.

    Researcher

    Uses a local Chroma knowledge base built from kb/knowledge.pdf, with Tavily web search as a fallback. Tool output is treated as untrusted data.

    Writer

    Drafts a short brief from the research. If the editor or the human left feedback, it revises to address it.

    Editor

    Approves the draft or returns one short fix. Each editor pass decrements a revision counter.

    Human verify

    Pauses the graph with a LangGraph interrupt and shows the draft. If the reviewer declines, the writer revises once more and the run ends.

    State

    FieldPurpose
    messagesConversation, appended with operator.add
    nextSupervisor's routing decision
    draft, critiqueCurrent brief and the editor's requested fix
    revisionsRevision counter, starts at 2 from the API
    approved, final_passHuman decision and the flag that sends the writer to END

    API

    The FastAPI app in api/main.py exposes:

    POST /details          { "task": "...", "thread_id": "demo" }  -> { "draft": ..., "error": ... }
POST /details/stream   server-sent events with writer tokens, ends with [DONE]

    It can also run in LangGraph Studio through langgraph.json, or in Docker with docker compose up --build.

    Run it yourself

    git clone https://github.com/Anubhav6205/langgraph-multi-agent-newsroom
cd langgraph-multi-agent-newsroom
cp .env.example .env      # add OPENAI_API_KEY and TAVILY_API_KEY
pip install -r requirements.txt
python kb/kb.py           # build the Chroma knowledge base
uvicorn api.main:app --port 8000
